Refund Shark uses a Next.js/React frontend with TypeScript, a FastAPI backend, and SQLite plus local files for documents, evidence, and audit history. This split keeps the finance workflow responsive while Python handles document parsing, typed validation, and reproducible calculations. SQLite makes the local demo easy to run without provisioning infrastructure.

The central design principle is “models read; code decides.” Claude Sonnet 5.5 extracts 16 structured SLA fields with supporting quotations, validated through Pydantic and checked against the source text. I chose structured extraction because contracts contain inconsistent language that is difficult to capture with rules alone. The model never determines eligibility or calculates money. A deterministic Python engine measures customer downtime, applies exclusions and credit tiers, checks prerequisites and deadlines, and uses Decimal arithmetic for amounts. Missing evidence or unsupported metrics route the case to review.

Read-only Ramp spend imports identify subscriptions, public status feeds surface incidents, and a Datadog adapter or uploaded logs supply customer-specific measurements. The workflow connects contracts, invoices, support tickets, human approval, and credit reconciliation. Versioned decisions and downloadable evidence bundles make each calculation inspectable and reproducible offline.

I prioritized trust and a reliable local demonstration over broad automation: pricing support is deliberately narrow, vendor submission is simulated, and live connector access remains unvalidated. Cached model runs make the demo reproducible without API credentials, but independent human reference review is still pending.

With more time, I would expand independently reviewed evaluations and vendor-specific measurement adapters, test live integrations, and add tenant isolation, authentication, PostgreSQL, object storage, durable background jobs, and approval-controlled vendor delivery.
